## 函数
- def定义函数
- 可变类型作为默认参数，这个参数会使用同一份。多次调用就会出现干扰的情况。为了避免这种情况参考如下示例
```python
def get_name(person_dict=None):
    if person_dict is None:
        person_dict = {}
    return person_dict.get("name")
print(get_name())
person_dict = {
    "name": "刘六"
}
print((get_name(person_dict)))
```
- 可变参数与可变关键字参数
  - 可变参数内部是一个元组
  - 可变关键字参数内部是一个字典
```python
# *name_list是可变参数(参数名可以随便写，关键是前面的*), **people_dict是可变关键字参数(参数名可以随便写，关键是前面的**)
def hello(*name_tuple, **people_dict):
    for name in name_tuple:
        print(name)
    for key, value in people_dict.items():
        print(key, value)
hello("a", "b", "c", name="1", age=18)
```
- 参数顺序
  - 普通参数
  - 默认参数
  - 可变参数
  - 可变关键字参数
- 返回值
  - 返回值可以有多个

## 递归
- 递归函数模板
```
 def f(参数, 携带的状态):
     # 1. 终止条件：最小问题怎么处理
     if 到达边界:
         做收尾的事 / return 基础结果

     # 2. 递之前：当前层先要做的事（可选）
     处理当前节点

     # 3. 递归：拆成一个或多个更小的子问题
     f(更小的输入)
     # 可能还有第二次、第三次调用（分治、树、多分支）

     # 4. 归之后：回到本层要做的事（可选，如回溯的撤销）

     # 5. 返回本层结果（可选）
     return 结果
```
- 递归三法则（写递归函数前自查）
```
1. 契约      一句话说清函数干什么
             → 我能用一句话描述 f(n) 返回什么吗？

2. 归纳假设  相信小规模输入已被正确解决
             → 我敢不敢直接相信 f(n-1) 是对的？

3. 递降性    问题规模严格变小，必然到达出口
             → 参数是不是单调变小？出口够得着吗？
```

## 闭包
- 满足三个条件，就构成了闭包：
  - 有嵌套函数（函数里定义函数）
  - 内层函数引用了外层函数的局部变量（这个变量叫“自由变量”）
  - 外层函数返回内层函数本身（注意：返回的是函数，不是调用结果）
- 核心
  - 内层函数把自己用到的外层变量“打包带走”了，外层作用域结束后，这些变量仍然活着
- 实现
  - 闭包对象.__closure__ 查看特殊cell的对象，cell对象引用着外层变量，所以垃圾回收不会清理它。每个闭包实例持有自己独立的 cell，所以每个闭包互相不干扰。

> Queue内置线程安全机制，不建议用普通list替代
- 关键方法:

  - join(): 等待所有put的任务都task_done

## 协程、线程、进程区别
- 协程由程序主动让出执行权
- 线程由操作系统调度，适合I/O并发
- 进程拥有独立资源，适合CPU并行
- 协程运行在事件循环中，切换成本低
- 协程不能自动让纯CPU计算并行
